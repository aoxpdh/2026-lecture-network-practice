# Lab 6 observations

## Task 1
동일 비용이면 처음 발견한 경로를 유지하며 이웃 순회와 heap의 노드 이름 순서로 결과를 결정한다. 실제 라우터는 ECMP로 여러 동등 비용 next hop을 설치하고 흐름별로 분산할 수도 있다.
u에서 w로는 직접 링크 비용 5보다 u-x-y-w의 비용 3이 작으므로 next hop이 x이다. u-x 단절 후 w는 x→w, x·y·z는 x→v로 바뀌며 v는 그대로 v이다.

## Task 2
국내 경로의 캠퍼스 이탈은 미확인이고 A의 외부 경로 3→4홉은 출구 후보다. 1.1.1.1은 A 13홉/11.295ms, B 17홉/34.160ms로 가까운 replica를 시사하나 위치는 모른다. Stanford CDN은 B의 ICMP에서 18홉/86.302ms로 도달했지만 해저 구간·케이블은 미확인이다. 별표는 응답 필터링·제한 또는 손실로 생길 수 있고, 별표 뒤 목적지 응답도 관측했다.
세 라우터 모두 직접 연결되지 않은 상대 loopback과 반대편 서브넷을 OSPF로 학습했다. interface down은 0.220초, 복구는 12.727초였고 무응답 장애는 30.815초, 복구는 14.142초였다. Hello/Dead=10/40초에서 무응답 감지는 마지막 hello 이후 남은 dead 시간에 좌우되며, 복구는 hello·인접 형성·LSA/SPF를 거쳐 비대칭이다.
r1→r3 비용을 10→100으로 올리자 r1의 r3 loopback 경로가 직접 next hop(비용 10)에서 r2 경유(20)로 0.279초에 바뀌었다. 무응답 장애보다 빠른 이유는 dead 감지 대기 없이 LSA/SPF가 진행되기 때문이며, 즉시 감지되는 interface down보다 반드시 빠르지는 않았다. 시간은 0.5초 polling·Docker overhead가 포함된 단일 실험의 FIB 관측 상한이다.

## Task 3
SPF 한 번에서 거리와 선택된 부모를 함께 저장하며 추가 메모리는 O(V)이다. 사용하지 않는 링크의 삭제·비용 증가와 더 짧거나 동률인 경로를 만들지 않는 추가·비용 감소는 SPF를 생략한다.
선택된 트리의 링크가 악화되거나 새로운 링크가 더 짧거나 동률 경로를 만들면 제공된 dijkstra_table로 재계산한다. 공식 1,000개 이벤트의 오답은 0개이며 SPF는 1,001→363회(63.7% 절감), 별도 6,000개 무작위 이벤트도 일치했다.
공식 wall time은 0.91→1.25초지만 개선판에만 검증용 SPF 1,000회가 포함된다. 양쪽 검증을 끄면 0.90→0.33초였으며, 라우터 적용은 이 측정과 함께 CPU 부담 감소·추가 메모리·갱신 정확성을 평가해야 한다.
